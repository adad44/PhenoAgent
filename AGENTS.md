# PhenoAgent — Unified Health Intelligence Platform
> Spec for AI coding agents (Claude Code / Codex). Read this file fully before writing any code.

---

## 0. Mission

Build **PhenoAgent** — a full-stack web app that aggregates health data from wearables, nutrition logs, bloodwork uploads, and training records into a single dashboard, then surfaces patterns via an AI health assistant called **Pheno**.

"Pheno" = phenotype: the observable expression of your body's state. The assistant doesn't give generic advice — it reads *your* data and explains *your* body.

## 1. Tech Stack

| Layer | Choice | Reason |
|---|---|---|
| Frontend | React 18 + Vite | Fast dev, good ecosystem |
| Styling | Tailwind CSS v3 | Utility-first, consistent |
| UI Components | shadcn/ui | Headless, composable |
| Backend / DB | Convex | Real-time queries, TypeScript schema, free tier |
| Auth | Convex Auth | Built-in, supports email/password + OAuth |
| File Storage | Convex Storage | PDF uploads, built into the platform |
| OAuth Server | Node.js + Express (thin) | Only for OAuth callbacks + Claude SSE streaming |
| AI Assistant | Anthropic Claude API (`claude-sonnet-4-20250514`) | Tool use, long context |
| Charts | Recharts | React-native, composable |
| Hosting (FE) | Netlify | Free tier, CI/CD from GitHub |
| Hosting (BE) | Render.com free tier | Thin Express server |

**Free-tier constraints:** Do NOT use paid services. Convex free tier supports 1M function calls/month and 64MB storage — sufficient for development and early users. Prefer Netlify over Vercel for frontend hosting.

**Architecture note:** Convex handles ALL database reads/writes via queries and mutations. The thin Express server exists only for two things: (1) OAuth redirect/callback flows that require server-side secrets, and (2) streaming Claude responses via SSE. Everything else goes through Convex.

## 3. Convex Schema (`convex/schema.ts`)

This is the single source of truth. Convex auto-generates TypeScript types from it. Do not define types manually — import them from `convex/_generated/dataModel`.

```ts
import { defineSchema, defineTable } from "convex/server";
import { v } from "convex/values";

export default defineSchema({
  // Sleep sessions
  sleepSessions: defineTable({
    userId: v.id("users"),
    source: v.union(
      v.literal("whoop"),
      v.literal("oura"),
      v.literal("garmin"),
      v.literal("manual")
    ),
    date: v.string(),                  // ISO date string "YYYY-MM-DD"
    totalSleepMin: v.optional(v.number()),
    remMin: v.optional(v.number()),
    deepMin: v.optional(v.number()),
    lightMin: v.optional(v.number()),
    awakeMin: v.optional(v.number()),
    sleepScore: v.optional(v.number()),
    hrvMs: v.optional(v.number()),
    avgHr: v.optional(v.number()),
    respiratoryRate: v.optional(v.number()),
    rawData: v.optional(v.any()),
  })
    .index("by_user", ["userId"])
    .index("by_user_date", ["userId", "date"]),

  // Nutrition logs
  nutritionLogs: defineTable({
    userId: v.id("users"),
    loggedAt: v.number(),              // Unix timestamp ms
    mealName: v.optional(v.string()),
    calories: v.optional(v.number()),
    proteinG: v.optional(v.number()),
    carbsG: v.optional(v.number()),
    fatG: v.optional(v.number()),
    fiberG: v.optional(v.number()),
    source: v.union(
      v.literal("manual"),
      v.literal("ai_scan"),
      v.literal("mfp"),
      v.literal("cronometer")
    ),
    rawData: v.optional(v.any()),
  })
    .index("by_user", ["userId"])
    .index("by_user_time", ["userId", "loggedAt"]),

  // Nutrition targets (one per user)
  nutritionTargets: defineTable({
    userId: v.id("users"),
    calories: v.optional(v.number()),
    proteinG: v.optional(v.number()),
    carbsG: v.optional(v.number()),
    fatG: v.optional(v.number()),
  }).index("by_user", ["userId"]),

  // Training sessions
  trainingSessions: defineTable({
    userId: v.id("users"),
    performedAt: v.number(),           // Unix timestamp ms
    name: v.optional(v.string()),
    sport: v.optional(v.string()),     // 'strength' | 'cardio' | 'cycling' | ...
    durationMin: v.optional(v.number()),
    sets: v.optional(
      v.array(
        v.object({
          exercise: v.string(),
          setNum: v.number(),
          weightLbs: v.optional(v.number()),
          reps: v.optional(v.number()),
          rpe: v.optional(v.number()),
        })
      )
    ),
    source: v.optional(v.string()),
    rawData: v.optional(v.any()),
  })
    .index("by_user", ["userId"])
    .index("by_user_time", ["userId", "performedAt"]),

  // Biomarkers / bloodwork
  biomarkers: defineTable({
    userId: v.id("users"),
    testedOn: v.string(),              // ISO date "YYYY-MM-DD"
    name: v.string(),                  // "ApoB" | "Ferritin" | "HbA1c" | ...
    value: v.number(),
    unit: v.string(),
    labRangeLow: v.optional(v.number()),
    labRangeHigh: v.optional(v.number()),
    optimalLow: v.optional(v.number()),
    optimalHigh: v.optional(v.number()),
    source: v.union(v.literal("manual"), v.literal("pdf_upload")),
    notes: v.optional(v.string()),
  })
    .index("by_user", ["userId"])
    .index("by_user_name", ["userId", "name"]),

  // Supplement stack
  supplements: defineTable({
    userId: v.id("users"),
    name: v.string(),
    doseMg: v.optional(v.number()),
    frequency: v.optional(v.string()),
    timing: v.optional(v.string()),
    active: v.boolean(),
  }).index("by_user", ["userId"]),

  // Daily journal
  journalEntries: defineTable({
    userId: v.id("users"),
    date: v.string(),                  // ISO date "YYYY-MM-DD"
    moodScore: v.optional(v.number()), // 1-10
    energyScore: v.optional(v.number()),
    notes: v.optional(v.string()),
  })
    .index("by_user", ["userId"])
    .index("by_user_date", ["userId", "date"]),

  // Wearable integrations
  integrations: defineTable({
    userId: v.id("users"),
    provider: v.union(
      v.literal("whoop"),
      v.literal("oura"),
      v.literal("garmin")
    ),
    accessToken: v.optional(v.string()),
    refreshToken: v.optional(v.string()),
    tokenExpiresAt: v.optional(v.number()),
    connected: v.boolean(),
    connectedAt: v.number(),
  })
    .index("by_user", ["userId"])
    .index("by_user_provider", ["userId", "provider"]),

  // Pheno chat history
  phenoMessages: defineTable({
    userId: v.id("users"),
    role: v.union(v.literal("user"), v.literal("assistant")),
    content: v.string(),
  }).index("by_user", ["userId"]),
});
```

## 4. Convex Auth (`convex/auth.config.ts`)

Use **Convex Auth** (`@convex-dev/auth`). Support email/password and optionally Google OAuth.

```ts
import { convexAuth } from "@convex-dev/auth/server";
import { Password } from "@convex-dev/auth/providers/Password";
import Google from "@auth/core/providers/google";

export const { auth, signIn, signOut, store } = convexAuth({
  providers: [
    Password,
    Google({
      clientId: process.env.GOOGLE_CLIENT_ID!,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
    }),
  ],
});
```

**Auth in queries/mutations:** Always call `ctx.auth.getUserIdentity()` at the top of every protected function and throw if null.

```ts
// Pattern used in every protected Convex function
const identity = await ctx.auth.getUserIdentity();
if (!identity) throw new Error("Unauthenticated");
const userId = identity.subject as Id<"users">;
```

**Auth in Express server:** Client sends Convex auth token as `Authorization: Bearer <token>`. Server verifies using the Convex HTTP client with the deploy key.

## 5. Convex Function Patterns

### 5.1 Query (real-time subscription)
```ts
// convex/sleep.ts
import { query } from "./_generated/server";
import { v } from "convex/values";

export const getSleepSessions = query({
  args: { days: v.optional(v.number()) },
  handler: async (ctx, args) => {
    const identity = await ctx.auth.getUserIdentity();
    if (!identity) throw new Error("Unauthenticated");
    const userId = identity.subject as Id<"users">;

    const since = Date.now() - (args.days ?? 30) * 24 * 60 * 60 * 1000;
    return await ctx.db
      .query("sleepSessions")
      .withIndex("by_user", (q) => q.eq("userId", userId))
      .filter((q) => q.gte(q.field("_creationTime"), since))
      .order("desc")
      .collect();
  },
});
```

### 5.2 Mutation (write)
```ts
export const addSleepSession = mutation({
  args: {
    date: v.string(),
    source: v.string(),
    totalSleepMin: v.optional(v.number()),
    // ... rest of fields matching schema
  },
  handler: async (ctx, args) => {
    const identity = await ctx.auth.getUserIdentity();
    if (!identity) throw new Error("Unauthenticated");
    const userId = identity.subject as Id<"users">;
    return await ctx.db.insert("sleepSessions", { userId, ...args });
  },
});
```

### 5.3 Action (external API calls)
Actions cannot directly read/write DB — use `ctx.runQuery` and `ctx.runMutation` inside them.

```ts
// convex/pheno.ts
export const getDailyBrief = action({
  args: {},
  handler: async (ctx) => {
    const identity = await ctx.auth.getUserIdentity();
    if (!identity) throw new Error("Unauthenticated");

    const snapshot = await ctx.runAction(api.pheno.buildSnapshot, {});

    const response = await fetch("https://api.anthropic.com/v1/messages", {
      method: "POST",
      headers: {
        "x-api-key": process.env.ANTHROPIC_API_KEY!,
        "anthropic-version": "2023-06-01",
        "content-type": "application/json",
      },
      body: JSON.stringify({
        model: "claude-sonnet-4-20250514",
        max_tokens: 200,
        system: PHENO_SYSTEM_PROMPT,
        messages: [{
          role: "user",
          content: `${snapshot}\n\nGive a 2-sentence readiness assessment for today. Be direct. No fluff.`,
        }],
      }),
    });

    const data = await response.json();
    return data.content[0].text as string;
  },
});
```


#### Streaming Chat (Express SSE)
Convex actions cannot stream SSE to the browser — use the Express server for this endpoint only.

`POST /api/pheno/chat`
- Header: `Authorization: Bearer <convex_token>`
- Body: `{ message: string, history: [{role, content}] }`
- Server: verify token → build snapshot via server-side Convex client → call Claude with `stream: true` → pipe as `text/event-stream`
- On completion: server calls Convex mutation to persist both messages to `phenoMessages`

#### Daily Brief (Convex action — no streaming needed)
- `useAction(api.pheno.getDailyBrief)` on dashboard mount
- Frontend caches: `localStorage.setItem("pheno_brief_YYYY-MM-DD", brief)`
- Short 2-sentence output — no streaming required

### 6.10 Integrations Page (`/integrations`)

Connection cards from `useQuery(api.integrations.getAll)`. OAuth flows go through the Express server because secrets cannot be in Convex client-visible actions.

#### WHOOP OAuth 2.0
- User clicks Connect → frontend opens `GET /api/integrations/whoop/auth`
- Express redirects to WHOOP OAuth; scopes: `read:sleep read:recovery read:workout read:profile`
- WHOOP redirects to `GET /api/integrations/whoop/callback`
- Express exchanges code for tokens → calls `ctx.runMutation(api.integrations.upsert, {...})`
- Sync: `POST /api/integrations/whoop/sync` → fetches 30 days → upserts `sleepSessions`

#### Oura Ring OAuth 2.0
- Same pattern; redirect to `https://cloud.ouraring.com/oauth/authorize`
- Scopes: `daily sleep workout`

#### Garmin Connect OAuth 1.0a
- `oauth` npm package in Express server
- Garmin Wellness API for sleep + activity summaries

#### Apple Health
- No direct OAuth (device-local)
- CSV import: user exports from Health app → Convex Storage upload → parse + ingest action

## 13. Notes for the Agent

- **Convex is the database.** All reads/writes go through Convex queries and mutations. No SQL, no Supabase, no Firebase.
- **No SQL.** Schema lives in `convex/schema.ts` using `defineTable` + `v` validators. Types are auto-generated — import from `convex/_generated/dataModel`.
- **Real-time is automatic.** `useQuery` subscriptions update the UI whenever data changes. No polling or WebSocket setup needed.
- **Actions for external APIs.** Claude calls, PDF parsing — use Convex `action` functions. Actions cannot directly read/write DB; use `ctx.runQuery` / `ctx.runMutation` inside them.
- **Pheno must always have context.** Never call Claude without first calling `api.pheno.buildSnapshot`.
- **Stream Pheno chat via Express.** Convex does not support SSE streaming to the browser. The Express server handles only this endpoint and OAuth callbacks — nothing else.
- **Handle undefined from useQuery.** `useQuery` returns `undefined` while loading. Always render loading skeletons, not errors, for the undefined case.
- **TypeScript everywhere.** Import types from `convex/_generated/dataModel`. Never manually duplicate schema types.
- **Mobile-first.** Dashboard grid: `grid-cols-1 md:grid-cols-2 lg:grid-cols-3`.
- **Rate limit** Express `/api/pheno/chat` — 20 req/min per user.
- **Never expose** `ANTHROPIC_API_KEY` or OAuth secrets to the client or Convex client-visible code.
- **Do not hallucinate provider API endpoints.** Verify WHOOP, Oura, and Garmin docs before implementing OAuth and sync logic.
